# 灵搭信息安全与数据安全基线

## 已落地的技术控制

- 所有业务 API 默认要求 JWT，只有登录、注册和健康检查公开。
- 生产环境拒绝使用默认或过短 `JWT_SECRET`，Swagger 默认关闭。
- CORS 仅允许配置的学生端和管理端域名，WebSocket 使用同一来源白名单。
- 登录/注册、图片上传和普通 API 分级限流。多实例部署时应迁移到 Redis 集中限流。
- DTO 拒绝未声明字段，减少批量赋值和越权参数。
- 私聊列表、历史和发送都要求已接受好友关系，不仅依赖前端隐藏按钮。
- 公告置顶和时间轴时间只能由管理员设置。
- 图片上传同时检查 MIME、文件大小和真实文件头，服务器生成随机文件名。
- 认证材料不放在公开静态目录，只允许申请人和正常状态管理员鉴权读取。
- 密码使用随机盐 `scrypt` 哈希，登录失败使用模糊错误避免学号枚举。
- 默认设置 `nosniff`、禁止 iframe、最小 Referrer 和浏览器权限策略。

## 学校服务器要求

- 强制 HTTPS/HSTS，后端只监听 `127.0.0.1`，MySQL 禁止公网访问。
- 数据库使用独立最小权限账号；生产密钥保存在权限 `600` 的环境文件或学校密钥管理系统。
- MySQL 开启每日备份与 binlog；数据库、公开附件和私密材料分类备份。
- 认证材料和数据库备份必须加密，备份副本不得与主机共用单一磁盘。
- 管理端建议限制在校内网/VPN，并由学校身份系统提供二次认证。
- 保留管理员审核、公告修改、内容下架和认证材料访问日志，日志中禁止记录 JWT、密码、手机号和材料原文。

## 数据生命周期

- 只收集组队、校园社区和身份审核必需数据，在界面上说明用途和可见范围。
- 认证材料建议在审核完成 90 天后自动删除，仅保留申请类型、结果、审核人和时间。
- 账号注销后删除或匿名化个人资料、认证材料和可识别聊天内容，法律或学校规章要求保留的数据除外。
- 恢复演练至少每学期一次，并记录 RPO/RTO 结果。
